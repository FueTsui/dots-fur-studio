# Dots · 毛绒实验室

使用 Three.js 制作的毛绒角色编辑器，可调整外形、颜色、眼型、眼镜、配饰和毛发，并导出 PNG 与 JSON。基于原 Dots 资源的外形与装配坐标，使用本项目的 GPU 毛绒着色器渲染。

[预览页面](https://fuetsui.com/#page-843c2384-7c92-474e-b383-f201f81d66ae) · [完整在线编辑器](https://fuetsui.com/demos/dots/index.html?preset=fanshu) · [下载公开版本](https://github.com/FueTsui/dots-fur-studio/releases)

网站预览嵌入的是适配版“番薯”预设；完整编辑器可继续修改角色。这是非官方个人项目，与 Dots 原产品及其权利人无隶属或认可关系。

## 运行

需要 Node.js 20.19+ 或 22.12+（CI 使用 Node.js 22）、支持 WebGL 2 的现代浏览器。下载源码后，在项目目录执行：

```powershell
npm ci
npm run dev
```

访问终端中的本地地址，默认 `http://127.0.0.1:5173/`。Windows 也可双击 `启动 Dots.cmd`。

验证并构建静态站点：

```powershell
npm test
npm run build
npm run preview
```

`npm run build` 输出到 `dist/`，使用相对路径 `./`，可部署到域名根目录或子目录。`npm run build:site` 使用 `/demos/dots/`，用于上面的个人网站部署。

Release 中的静态站点包已包含运行资源，解压后用 HTTP 静态服务器访问；不要直接以 `file://` 双击打开 HTML。运行模型、缩略图和前端依赖均随站点提供，不请求 CDN 或原站。装配资源约 170 MB，按当前选项加载，不会一次下载全部。安装开发依赖需要网络；安装完成后，开发运行和构建不需要重新提取原资源。

## 使用

- 11种形状、11种预设颜色与自定义颜色、9种源眼型、5款眼镜与无眼镜、8种配饰与无配饰。
- 形状与配饰均支持拾色器和HEX输入，可输入 `#RGB` 或 `#RRGGBB`；共用色盘包含原页的炭黑 `#1f1f1f`、棕色 `#8c4a2b`。形状自定义颜色随切换形状保留，与配饰颜色独立。配饰支持恢复原色，各款独立记忆颜色；所有颜色随本地保存和JSON导出保留，旧存档中的预设色继续兼容。
- 针织帽、礼帽、贝雷帽、圆球和三瓣发饰的短毛同步改色；皇冠使用独立亮面材质，改色保留高光。
- 双耳圆头仅使用内嵌圆眼；其余形状支持另外8种眼型。两种带耳朵的主体只支持耳机或领结。原引擎最多选择1件配饰，界面保留这些限制。
- “毛绒”中实时调整8项参数，旁边可精确输入；画质限制实际绘制密度，状态栏显示当前根数。
- 点击名字编辑；“保存”写入当前浏览器本地存储，刷新自动恢复。它不会修改用户在 ChatGPT 的原始角色。
- PNG 导出当前角色画面；JSON 导出外形选择、毛绒参数、网格尺寸、顶点数、安装坐标与来源信息。
- “查看原始外形参数”展开当前主体与配件参数。
- 拖动旋转、滚轮缩放、双击回正，空格或暂停按钮控制动画。支持手机布局及系统减少动态效果设置。
- 鼠标带动眼睛和头部独立跟随；小范围鼠标移动也有明显眼动，眼睛更快、头部稍慢，离开预览或窗口失焦后回正。暂停仅冻结自动动画，仍可用鼠标看向不同方向。

## 毛绒参数

| 参数 | 作用 | 默认 | 范围 |
| --- | --- | --- | --- |
| length | 毛发长度，越高越长 | 0.10 | 0.035–0.22 |
| density | 目标毛发数量，单位千根 | 125 | 35–180 |
| thickness | 单根毛发宽度 | 0.46 | 0.15–0.85 |
| mess | 毛发方向随机偏移 | 1.10 | 0–2 |
| curl | 卷曲幅度 | 1.60 | 0–3 |
| gravity | 向下弯曲力度 | 0.45 | 0–1.5 |
| bright | 毛绒亮度 | 1.00 | 0.6–1.6 |
| rim | 边缘补光强度 | 0.85 | 0–1.8 |

这些是本项目的毛绒着色器参数，不是从原始 Dots 页提取的毛发参数。原始网格没有直接可编辑的“半径/圆角”等设计旋钮，本项目保留其顶点、法线、索引、RGB、包围盒与烘焙后的安装位置。

## 来源与实现

- 原资源目录：`orbit-character-a46c99f7e8749621/fec1363c5aea4fbb`。
- 原几何 revision：`7f2e673cd9cff752c137d3d858bc4ddb530dda34fe9c2e1fb23a94b2831adf1d`。
- `public/orbit/decoded/` 保存56个已解码原网格；`public/orbit/assemblies/` 保存374套原引擎装配结果。
- 透明眼镜会改变眼距，已提取各眼型的对应组合。原生材质RGB与几何保留，灯光和材质模型适配到 Three.js。
- `src/original-geometry.js` 读取原模板几何，`src/original-accessories.js` 读取原引擎安装后的几何。模板厚度和装配后的厚度不同，实际渲染采用后者。
- `src/fur.js` 用 `MeshSurfaceSampler` 按原网格三角形面积采样毛根，使用 `InstancedBufferGeometry` + `ShaderMaterial`。每根毛8顶点6三角形，GPU处理摆动、卷曲、下垂与触碰。眼周进行局部修剪，保留原生眼睛位置。
- 默认主体125,000根，针织帽/礼帽/贝雷帽/圆球/三瓣发饰采用相同短毛层，每款额外18,000根短毛；高/中/低画质上限180k/85k/40k。自动档可降低画质。
- `src/catalog.js` 集中定义目录与参数；`src/settings.js` 校验保存数据；`src/main.js` 负责动画、切换、有限缓存和GPU资源释放。

本项目的毛绒与动态是自定义复现，未获取视频作者的原着色器，没有逐根毛发物理碰撞。性能取决于设备、分辨率与浏览器。浏览器可只读查询 `window.__dots.state`。

## 眼睛跟随的原版校准与展示增强

以用户指定页面实际加载的原版 WASM 渲染器为参考，在独立测试实例中采集每个眼部件的矩阵，剔除头部运动和眨眼干扰。`public/orbit/gaze/profiles.json` 覆盖243种眼睛与透明镜框组合，复用150种独立布局，共15,350个部件矩阵。所有数据均本地加载。

- `src/eye-gaze.js` 保留原版贴面矩阵的缩放、剪切、旋转和限位。普通眼型用3×3采样场；内嵌眼型采用更密的11×11/15×15网格和仿射旋转插值，保持眼球表面的转动半径。
- `src/gaze-motion.js` 根据65帧原版响应拟合眼睛、头部各自的临界阻尼；模型角频率仍为眼睛 `52.5 s⁻¹`、头部 `22.3 s⁻¹`，约0.1秒/0.23秒接近目标。这是实测拟合模型，并非解出的原版内部常数。
- 原版头部最大水平角约 `±0.055 rad`（3.15°）、垂直角约 `±0.035 rad`（2.01°）。这些数值保留作校准参考，当前展示角度采用下面的增强值。
- 眼周毛发修剪区同步跟随；眼白、瞳孔、高光和眼皮按各自矩阵更新；镜框及其他配饰保持原位。

`src/gaze-input.js` 在原临界阻尼前增加展示用输入映射，增益系数为 `2.1`。曲线增强中央和中间区域的鼠标响应，接近边缘时逐渐放缓，只在边界达到原眼球采样极限。当前头部展示范围为水平 `±0.085 rad`（4.87°）、垂直 `±0.055 rad`（3.15°），约为原版的1.5倍；仍按 `YXZ` 顺序组合，向上看时俯仰为负。原始眼部矩阵采样、眼球极限及 `52.5/22.3` 的动态拟合参数均未改动。

连续运动使用采样插值和动态拟合，不能视为原版连续求解器的逐帧完全复制。用于自动化回归的65帧响应样本随仓库保存在 `tests/fixtures/gaze-step-response.json`。

## 验证

- `npm test` 覆盖486组合法眼睛×眼镜搭配并轮换配饰；校验11种主体、962份独立几何、材质、索引、法线、缓存释放与保存参数校验。形状颜色检查覆盖预设色、自定义HEX规范化、非法值回退、保存读取、旧存档兼容及切换形状/配饰后保留颜色。
- 同时验证全部注视采样、30种动态组合、眼镜不随眼睛移动、回正无累积、毛发遮罩、原版65帧响应拟合及30/60/120 FPS一致性；另检查增强输入的有限性、对称性、单调性、无提前限位、小范围增益，以及快速反向后的有界运动与回正。
- 配饰颜色测试覆盖8款配饰×11色，逐一检查针织帽、礼帽、贝雷帽、圆球和三瓣发饰这5款配饰的短毛层、shader同步及原色恢复，并检查独立记忆和旧存档兼容。
- 装配资源完整审计：`public/orbit/assemblies/audit.json`。

自动化测试验证 Node.js 中的数据、几何、材质、参数保存和动画计算；浏览器、WebGL 渲染和设备性能仍需实际运行检查。GitHub Actions 对推送与 Pull Request 执行安装、测试和构建。
